# Language

Every word the app shows comes from a catalog, one file per language. English is the only language that ships today; adding another is adding one file.

## Where things are

| Piece | File | What it does |
| --- | --- | --- |
| The catalogs | `src/locales/<tag>/translation.json` | One per language. The same layout and file name the sibling apps use. |
| Which languages exist | `src/locales.ts` | Reads the folders on disk. Nothing else lists them. |
| The app's language | `src/i18n.ts` | Sets up i18next, picks the starting language, exposes `setLanguage()`. |
| Core's words | `src/core/text.ts` | `tr()`: how code outside React asks for text. English by default; the app installs its translator at boot. |
| The picker | `src/components/LanguagePicker.tsx` | Shown in Settings once more than one language ships. |

## Adding a language

1. Copy `src/locales/en/translation.json` to `src/locales/<tag>/translation.json` (`de`, `pt-BR`, `zh-CN`).
2. Translate the values. Keep the keys and every `{{slot}}`. Plural keys end in `_one` and `_other` in English; a language with more forms adds the ones it needs (`_few`, `_many`).
3. Run `npm test`. `src/locales.test.ts` fails if the new file is missing a key, has one English does not, or uses a slot English does not have.

That is all. The language appears in the picker, and the device's language is matched to it at startup.

## Rules for code

- **No text in a component.** `const { t } = useTranslation()` and `t('section.key')`. The lint rule `i18next/no-literal-string` fails on text between tags and in the props that carry text (`title`, `aria-label`, `placeholder`, `label`, `hint` and so on).
- **Outside React, `tr()`** from `src/core/text.ts`, called when the text is needed. Never build a table of labels at module load: it would be frozen in whatever language was active at that moment. That is why `EVENT_META`, `VERDICTS`, `CATEGORIES` and `CYCLES` carry no words; ask `eventKindLabel()`, `verdictLabel()`, `categoryLabel()`, `cycleLabel()` instead.
- **Keys are typed.** `t()` and `tr()` only accept keys that are in the English catalog, so a typo does not compile. `src/locales.test.ts` also reads the source and fails on a key nothing asks for.
- **Whole sentences.** A value goes in a slot (`"Last synced {{when}}"`), a count goes through a plural, markup inside a sentence goes through `<Trans>`. Never glue translated pieces around a value: word order is not the same everywhere.
- **Dates and numbers are not translated, they are formatted.** `fmtDay()`, `fmtMoment()`, `relative()` and `money()` use the platform's own knowledge of each language (`Intl`), so "in 3 weeks" and "Sep 4" need no catalog entries. Never call `dayjs().format()` with a display pattern.
- **Core stays pure.** `src/core` imports `./text`, never i18next or React.

## How the language is chosen

1. A choice made in the picker, kept on the device under `tg_lang`.
2. Otherwise the first of the device's languages that ships.
3. Otherwise English.

Dates and numbers follow the language, and the device's region within it: an English catalog on a British device writes "4 Sept", not "Sep 4".

## How it differs from the sibling apps

lastGLANCE loads `/locales/<lng>/translation.json` over HTTP at runtime and precaches those files in the service worker. Here the catalogs are part of the build instead:

- English is in the main bundle, so the app can always speak, and core has words even with no translator installed (a headless run, a test).
- Every other language is its own hashed chunk. The service worker precaches it like any other build file, and it can never be a version behind the code asking it for a key.
- Nothing is fetched, so the rule that every request goes through `src/sync/shellFetch.ts` has no exception to make, and a shell that serves the app from a file path needs no special case.

## What is still English

- The `message` on a refused write from outside (`src/intents/handleIntent.ts`). It is written for the developer of the widget or tool that sent it; the `code` beside it is what a caller acts on.
- Console warnings, and errors that only fire on a programming mistake.
- `public/manifest.json` (the install name and shortcut labels). A web manifest has one language.
- The web lookup reads the English Wikipedia.

## Other surfaces

The snapshot (`docs/snapshot.md`) carries text in the device's language and says which in `locale`. A native widget or notification that shows snapshot text needs no string catalog of its own for it; one that adds its own words (a button on a notification) will, and should take them from the same catalog files so there is one place to translate.
